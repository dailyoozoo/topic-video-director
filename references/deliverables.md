# 阶段交付模板

按阶段复制需要的部分，不要求一次填完。示例字段是文档约定，不是任何渲染脚本已经支持的输入格式。

## 任务与续接记录：job.md

```markdown
# 任务
主题：
目标观众与平台：
看完要理解的一句话：
画幅、预计时长、语言：
画风/参考样片：
现有工具、角色动作、配音与素材缺口：
当前阶段：research / script_review / storyboard_review / production / delivered

## 已有确认
脚本：版本、文件路径、确认日期、用户原话；未确认则写 pending
分镜：版本、文件路径、对应脚本/声音、确认日期、用户原话；未确认则写 pending

## 下一步
可直接做的工作：
需要等待的决定及原因：
已作废的下游产物：
```

只有收到用户真实回复才能填批准记录。空白、模型自评、工具 PASS、等待超时都不构成批准。

## 来源表：research.md

| 来源 ID | 页面标题 / URL | 发布或更新日 | 访问日 | 已读正文与证据位置 | 支持内容 / 限制 |
|---|---|---|---|---|---|

日期未知就写未知，禁止用访问日期冒充发布日期。证据位置可用段落标题、短摘录或原报告页码。

| 事实 ID | 拟用说法 | 性质：事实/推断/建议 | 来源 ID | 适用条件与核实状态 |
|---|---|---|---|---|

仅完成来源表不等于核实结论，必须检查页面是否真的支持拟用表述。

## 脚本包：script-v01.md

```markdown
# 脚本 v01
主题角度：
目标观众：
预计时长：估算，待配音测量
内容取舍与默认假设：

| 段落 ID | 逐字口播 | 预计秒数 | 必须上屏的事实文字 | 事实 ID |
|---|---|---|---|---|

开头为何值得看：
中段如何讲清楚：
结尾留下的结论或行动：
待确认点：内容方向、表达、时长和具体台词。
```

脚本先解决“说什么”，不用在此阶段承诺尚不存在的镜头和角色动作。非事实性的衔接语无需硬配引用。

## 分镜包：storyboard-v01.md

```markdown
# 分镜 v01
对应脚本：script-v01.md，已批准
声音文件与实测时长：缺少时写 estimated，不能写已锁定
视觉规则：角色参考、主色/辅色、字体、字幕安全区、标题层级
素材路线：动作视频 / 已验收动作库 / 分层绑定 / 待验证生成

| 镜头 ID | 台词段落 | 起止秒数 | 观众要看到的信息 | 构图与主动作 | 文字/字幕 | 衔接 | 素材及状态 | 关键画面路径 |
|---|---|---|---|---|---|---|---|---|

关键画面总览：实际文件链接
技术不确定性与占位素材：
本次确认范围：主要镜头、造型、风格、动作路线；实测/估算的时长状态。
```

一个可执行的镜头描述示例（仅示范写法，不是已制作素材）：

> S02，对应 P02：“先运行测试，再检查改动”。4.20–8.00 秒。画面上方逐项点亮“运行测试 / 检查改动”；下方角色指向第一项，随后点头。使用动作库 `point_up` 接 `nod`，嘴部跟随 P02 人声。字幕最多两行，避开嘴部。背景保持低对比，结尾切向测试结果画面。动作文件与关键图未提供时，状态必须写“缺少素材”。

弱例：“科技感，角色很生动，转场高级”。这没有定义镜头要传递的信息、可用素材和可检查动作。

## 制作与验收：qa.md

```markdown
# 制作记录
脚本、分镜、声音的最终版本：
角色/动作资产及来源：
实际执行命令、退出码、输出路径：
动态试片与修复结果：

## 验收
技术：PASS / FAIL，报告链接
静帧视觉：已检查 / 待检查，证据与问题
连续动作：已播放检查 / 待检查，范围与问题
声音与同步：已试听检查 / 待检查，范围与问题
脚本一致性：逐段核对台词、字幕、画面事实文字
用户创意确认：对应版本
仍未解决的问题：
```

最终状态可为“制作完成，试听待完成”，不能用单一“全部通过”隐藏未知项。
